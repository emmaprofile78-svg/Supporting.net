Thank you for your interest in contributing to Supporting.net! We welcome contributions from the community. To make collaboration smooth please follow these guidelines.

How to contribute
- Fork the repo and create a branch: `git checkout -b feat/your-feature`
- Keep changes focused and small; one logical change per PR
- Add tests for new behavior and ensure existing tests pass
- Update the README and docs for any public API changes
- Open a pull request describing the problem, your solution, and any notes for reviewers

Code style
- Keep formatting consistent with the repo's .editorconfig (if present)
- Use `dotnet format` or your IDE's formatter before committing

Commit messages & branches
- Use clear commit messages and reference issue numbers when applicable
- Branch names: `feat/`, `fix/`, `chore/`, `docs/`, `perf/` followed by a short description

Reviews & CI
- All PRs should pass CI and include tests where relevant
- Be responsive to review comments and iterate on feedback

Maintainers
- Maintainers will review and merge PRs. If you need help, open an issue describing your intent.

Code of Conduct
- By participating, you agree to follow the project's [Code of Conduct](CODE_OF_CONDUCT.md).
